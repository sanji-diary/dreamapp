# 인수인계 (2026-11-17 기준)

다른 컴퓨터나 새 대화에서 이 작업을 이어받을 때 먼저 읽는 문서입니다.
지금 상태, 지켜야 할 약속, 남은 일을 적었습니다. 실행 방법은 `README.md`에 있습니다.

## 한눈에

- 꿈의 숲 교회 소년부(초등 4-6학년 약 45명, 교사 약 12명) 웹앱 "꿈의숲키우기".
  아이는 미션을 하고 물방울로 나무를 키우며, 교사는 출석·교적부·심방·고민을 관리합니다.
- 실제 서비스: https://dreamforest-level-up.vercel.app (아이 화면), `/staff` (교사·관리자 화면)
- 작업 가지: `claude/zealous-carson-axtlbt`. 이 가지에 올리면 Vercel이 자동으로 배포합니다.
- 서버는 Vercel 도쿄(hnd1), 데이터베이스는 Supabase(ap-northeast-1). 마이그레이션은 `migrations/`의 SQL이 순서대로 자동 적용됩니다.
- 모든 표에 Supabase 보안 잠금(RLS)이 켜져 있고(`migrations/008_rls.sql`), Supabase REST API의 공개 역할(anon, authenticated)은 표에 접근하지 못합니다. 앱은 표 주인(`postgres`)으로 접속하므로 영향이 없습니다. **표를 새로 만드는 마이그레이션에는 `alter table ... enable row level security`를 꼭 넣습니다**(빠뜨리면 `test/rls.test.ts`가 실패).

## 로컬에서 실행

Node.js 22 이상과 git이 필요합니다.

```bash
npm install
```

```bash
npm run dev
```

- `DATABASE_URL`이 없으면 `.data/`에 시험용 데이터베이스(PGlite)가 생기고 예시 데이터가 들어갑니다.
- 교사 화면 `/staff/login`에는 시험용 로그인 버튼이 나옵니다(김인성 관리자, 박지현 담임, 이부장, 최기본).
- 아이 화면 첫 화면에는 "시험용 입구"가 나옵니다. 예시 아이의 비밀번호는 1234입니다.
- 시험용 입구와 시험용 로그인은 실제 서비스에는 나오지 않습니다.

검사는 올리기 전에 네 가지를 모두 돌립니다.

```bash
npx next typegen && npx tsc --noEmit && npm run lint && npx vitest run
```

```bash
PGLITE_DIR=memory DREAM_SEED=off npx next build
```

테스트는 파일마다 메모리 데이터베이스를 따로 띄워 메모리를 많이 씁니다(파일당 약 1.5GB, 동시에 3개).

## 환경 변수 (값은 Vercel 설정에만 있음)

`DATABASE_URL`, `SESSION_SECRET`, `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`, `ADMIN_INVITE_CODE`, `APP_URL`.
선택: `SHEPHERD_GAME_ORIGIN`(〈한 마리 어디 갔어?〉 게임 서버 주소. 없으면 공개 게임 주소를 씀. 비밀 값 아님).
로컬 전용: `PGLITE_DIR`(데이터 폴더), `DREAM_SEED=off`(예시 데이터 끄기).

## 지켜야 할 약속

- 비밀 값(위 환경 변수의 값, 초대 코드)은 대화창이나 저장소에 적지 않습니다. Vercel 설정에만 넣습니다.
- 전도사님의 이메일 등 개인 정보는 외부로 내보내지 않습니다.
- PR은 요청이 있을 때만 만듭니다. 작업과 배포는 위 작업 가지에서만 합니다.
- 저장소 안(커밋 메시지, 주석, 문서)에 AI 모델 이름을 적지 않습니다.
- 디자인은 승인된 시안(`design-reference/`, 아래 화면 시안 링크)을 따릅니다. 흔한 템플릿처럼 보이면 안 됩니다.
- 교회학교 앱입니다. 벌점, 개인 순위, 압박을 주는 장치를 넣지 않습니다.
- 교사 중에는 연세가 있는 분도 있습니다. 화면과 문구는 짧고 쉬워야 합니다.
- 화면은 갤럭시 폴드에서도 잘리면 안 됩니다. 폭 280, 344(접은 화면), 390, 768, 884(펼친 화면), 1280(컴퓨터)에서 확인합니다.

## 확정된 규칙

- 한 주 물방울 한도 12개(포인트는 한도 없음). 나무 단계에 필요한 물방울 2·4·6·8·10·10(한 그루 40개). 수확 보너스 50P.
- 나무는 시들지 않고, 쉬어도 잃는 것이 없습니다. 장부(`drop_ledger`, `point_ledger`)는 더하기만 하고, 정정은 반대 줄로 남깁니다.
- 미션은 세 가지로 나뉩니다(`missions.mode`).
  - 고정(`fixed`): 매주 나옴. 주일 예배 출석(2개·20P), 이번 주 말씀 쓰기(2개·15P), 가정예배 드리기(3개·30P), 오늘의 말씀 읽기(매일, 물방울 없이 2P).
  - 순환(`pool`): 보관함에서 매주 3개가 오래 안 나온 것부터 자동으로 나오고, 관리자가 그 주 것을 바꿀 수 있음.
  - 기간(`dated`): 시작일과 끝나는 날을 정한 미션.
- 말씀 쓰기: 여러 절 가능, 한 절씩 씀. 띄어쓰기와 문장부호까지 똑같아야 통과하고, 통과하면 선생님 확인 없이 적립. 틀리면 어디부터 다른지 표시.
- 자유 글 미션은 쓰면 바로 적립. 쓴 글은 그 아이의 정보를 열 수 있는 교사가 읽을 수 있고(아이 정보 › 활동), 아이 화면에도 그 사실을 적어 둠.
- 교사 확인 미션은 아이가 "확인 요청"을 누르면 교사의 할 일에 뜸. 돌려보내면 아이에게 "선생님이 다시 해 달라고 했어요"가 보임.
- 출석은 주일에만 기록. 결석으로 고쳐도 물방울이 0 아래로 내려가지 않음.
- 반가워 물방울: 출석을 부른 최근 두 주일을 모두 빠졌다가 다시 온 주일에 2개. 주간 한도와 따로 계산.
- 고민 글은 아이가 고른 사람만 읽음. 다른 화면에는 내용이 나오지 않음.
- 우리 숲(`/forest`, 첫 화면의 "우리 숲" 버튼): 소년부 전체가 함께 키우는 입체 숲 섬. 교회가 가운데 있고 64가지가 정해진 순서(`src/lib/forest.ts`의 `FOREST_ITEMS`)로 생김.
  - 주일마다 1가지. 지난주(주일~토요일)에 승인된 미션이 활동 중인 아이 한 명당 평균 3개 이상이면 1가지, 5개 이상이면 2가지가 더 생기고 물방울 비가 내림(`BUSY_STEPS`, 바꿔도 됨).
  - 그 주를 처음 열 때 `forest_weeks`에 한 줄 적고 다시 고치지 않음. 그래서 숲은 줄어들지 않음. 처음 누군가 열어 본 주가 시작 주.
  - 아이 화면에는 숫자가 없음. 이번 주에 생긴 것의 이름, 바쁜 주의 비, 행사 문구만 보임.
  - 계절은 실제 날짜(3~5월 봄 …). 행사: 설날(앞뒤 3일, 봄 모습), 부활절(종려주일~다음 토요일), 여름성경학교(7월 20일~8월 10일), 추수감사절(11월 셋째 주일 앞뒤 한 주), 성탄절(12월 한 달). 설날 날짜는 `SEOLLAL` 표에 2035년까지 있음.
  - 낮·저녁·밤은 한국 시각과 계절로 정함(`timeOfDay`).
  - 입체 그림은 `src/components/kid/forest/scene.ts`(three.js, 숲 화면에서만 불러옴). 승인된 시안: https://claude.ai/artifact/RHfnpLLzemBGoiJXrex4Fj (다섯 번째 판까지 반영)
  - 살아 있는 숲(다섯 번째 시안): 풀·꽃·나무가 바람에 흔들리고 동물이 걸어 다님. 단풍나무·미루나무·버드나무, 통나무 의자 옆 모닥불, 저녁과 밤에 땅에 비치는 불빛, 섬 아래의 덩굴·뿌리·떠다니는 바위.
  - 새로 생기는 순간: 그 휴대폰에서 그 주의 새것을 처음 볼 때(`localStorage`의 `dream-forest-seen`) 화면이 새로 생긴 것마다 다가가고 이름표가 뜸. 하늘에 생기는 것은 말로만 알림. 움직임 줄이기를 켠 휴대폰에서는 하지 않음.
  - 눌러 보기: 동물(깡충 뛰고 하트), 나무(흔들리며 잎이 떨어짐), 교회(종이 울리고 문이 잠깐 열림), 연못(물결). 미션이나 보상과 이어지지 않음. 참여를 요구하는 장치는 넣지 않기로 함(나무 키우기와 이미 이어져 있어서).
  - 주일에는 교회 문이 열려 있고 종이 흔들림. 밤에는 가끔 별똥별, 바쁜 주의 비는 숲을 열고 조금 뒤 그치며 무지개가 뜸, 겨울 밤 중 날짜가 3의 배수인 날에는 오로라(`auroraNight`).
  - 소리(종, 깡충, 물소리)는 처음엔 꺼져 있고, 숲 화면 오른쪽 위 단추로 켬(휴대폰에 기억). 예배 중에 소리가 나지 않게 하려는 것.
- 미션게임(게임 미션, `src/games/registry.ts`): 아이에게는 늘 "미션 목록 → 미션 화면 → 게임 → 미션 완료" 한 가지 흐름. 어떤 게임인지, 혼자인지 둘이인지, 무엇을 하면 끝나는지는 게임 목록에만 적혀 있어서 주마다 게임을 바꿔도 화면은 그대로.
  - 관리자가 미션을 만들 때 "게임"을 고르고 게임 하나를 고름. 물방울·포인트·기간·횟수는 다른 미션과 똑같이 미션에서 정하고, 주간 한도 12개도 똑같이 적용됨.
  - 앱 안에서 도는 게임(`host: "local"`, 짝 맞추기): 시작 토큰으로 확인(`src/lib/kid/game-proof.ts`).
  - 게임 서버가 따로 있는 게임(`host: "hosted"`, 〈한 마리 어디 갔어?〉): 미션 화면이 게임을 틀(iframe) 안에 띄움. 완주는 게임 서버가 판정하고, 앱 서버가 게임 서버에 직접 물어본 뒤에만 미션 완료로 기록(`src/lib/kid/hosted-game.ts`, 표 `game_launches`·`game_results`). 브라우저가 보내는 "끝났어요"는 믿지 않음.
  - 같은 완주는 한 번만 기록(`game_results`의 고유 규칙). 완주 직후 앱을 닫아도 다음에 첫 화면이나 미션 목록을 열 때 다시 물어봐서 넣어 줌(지난주 것까지, 완주한 날짜 기준).
  - 둘이 하는 게임은 두 아이가 각자 자기 계정의 미션에서 열어야 둘 다 받음. 완료한 게임 미션은 혼자 하는 게임이든 둘이 하는 게임이든 다시 열어 할 수 있음(한 번 더 하기, 친구 도와주기). 더 받지는 않음.
  - 〈한 마리 어디 갔어?〉 소스는 `games/shepherd-coop/`(게임만의 테스트는 그 폴더에서 `npm test`). 지금은 공개 게임 주소를 그대로 씀. 게임을 고쳐서 다른 곳에 올리면 Vercel 환경 변수 `SHEPHERD_GAME_ORIGIN`에 새 주소(https://… 까지만)를 넣음.
  - 새 게임 넣기: 게임 목록(`registry.ts`)에 한 줄, 게임 서버가 있으면 `hosted-game.ts`의 `HOSTED`에 주소와 "끝난 것으로 보는 조건"을 한 줄. 게임 서버가 지켜야 할 약속(주소 모양, 끝났다는 알림, 결과 확인 주소)은 `hosted-game.ts` 맨 위에 적혀 있음.
- 아이 로그인: QR 카드 또는 함께 쓰는 가입 QR + 비밀번호 4자리(5번 틀리면 10분 잠김). 교사 로그인: 카카오.

2. **직접 따라 해 보는 확인표**: 시험용 반과 아이를 만들고, 미션 종류마다 숫자가 맞게 들어오는지 순서대로 확인하는 안내. 1번이 끝난 뒤 그 화면 기준으로 작성.
3. 실제 기기 확인(전도사님이 직접): 갤럭시 폴드, 아이폰 홈 화면 아이콘, 키보드가 입력 칸을 가리는지, 카카오톡 안 브라우저, 카메라로 QR 찍기.
4. **관리자 화면 두 번째 시안의 남은 부분**: 화면 모양은 바꿨고, 시안에 있지만 아직 없는 기능은 따로 만들어야 함. 글 제목, 사진 여러 장, 임시 저장과 날짜 정해 올리기, 글 꾸미기(굵게·큰 글씨·구분선·링크), 글 여러 개 한꺼번에 지우기·찾기, 교적부에서 보호자에게 전화·문자, 반 편성 화면에서 담임 바꾸기, 휴대폰 관리 홈 시안(지금은 숲 그림 홈 그대로).
5. 우리 숲 다음 단계: 실제 휴대폰에서 움직임의 세기·다가가는 거리·소리를 보고 다듬기, 새 학년이 되면 "올해 우리 숲" 그림으로 남기고 새 숲 시작(지금은 `forest_weeks`를 비우면 새로 시작), 여름성경학교 날짜를 관리자가 정하기, 실제 기기에서 속도 확인(오래된 휴대폰).
6. 미션게임 다음 단계: 실제 휴대폰 두 대로 〈한 마리 어디 갔어?〉를 끝까지 해 보기(아이폰·갤럭시, 카카오톡 안 브라우저). 게임 쪽에서 고칠 것 두 가지는 게임을 다시 올려야 함: 앱에서 연 아이는 이름을 다시 적지 않게 하기, 두 자리 모두 앱에서 연 경우에만 완주를 기록하기(지금은 한 아이가 휴대폰 두 대로 혼자 두 자리를 채워도 자기 몫 한 번은 받을 수 있음).
7. 작은 것: 새로 가입한 아이가 14일 동안 목록에 남는 것, 컴퓨터 화면에서 포인트 조정 위치, 푸시 알림(보류), 실제 아이 정보를 넣기 전에 Supabase 유료 요금제 검토.

## 시험 데이터 지우기

실제 서비스를 처음 상태로 되돌릴 때는 `tools/reset/reset-keep-admin.sql`을 Supabase SQL 편집기에서 실행합니다.
관리자 계정과 기본 설정만 남고 나머지는 모두 지워집니다(되돌릴 수 없음). 자세한 것은 `tools/reset/README.md`.
앱에 표를 새로 만들면 이 파일의 지우는 목록에도 넣어야 합니다(빠뜨리면 스크립트가 멈추고, 테스트도 실패함).

## 확인 도구

`tools/checks/`에 화면을 여러 크기로 열어 옆으로 잘리는 곳을 찾는 스크립트가 있습니다.
로컬 서버(`npm run dev`, 3000번)가 켜져 있어야 하고 Playwright가 필요합니다. 사진은 `tools/checks/out/`에 저장됩니다.

```bash
node tools/checks/staff-screens.cjs /staff /staff/attendance /staff/approvals
```

node tools/checks/kid-missions.cjs demo-2 390 844
